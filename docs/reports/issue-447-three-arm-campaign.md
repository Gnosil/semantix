## 2. 链路有效性（本实验的第一结论）

**记忆供给-注入全链首次在真实 SWE 基准上端到端工作。**

- strict 臂 33/36 任务产生真实 provider 交付的注入块（交付计数按 S8 新口径：仅 provider 接受后记录），3 个零注入任务全部是各 repo 的**第一个任务**（冷启动库为空——课程效应的预期行为，非缺陷）。
- 三臂分离严格符合设计：shadow 全程 0 注入但有 reuse 诊断；off 全程 0 注入。
- 注入块带完整溯源（source session / base commit / origin=session-auto / `applicability=historical_observation`）。
- 对照 2026-09-18 之前的状态（注入结构性不可达、实测 0），修复目标**已达成并经真实验证**。

## 3. 收益结论（必须诚实）

**resolve 差异不显著，不能宣称记忆注入提升了通过率。**

- strict 40.0% vs off 42.9%：配对差 −1 题（2 vs 3），在 n=35 下远在噪声范围内；shadow（有诊断无注入）反而最高 45.7%，说明臂间波动主要是模型随机性。
- **成本侧为负向信号**：strict 每 prompt tokens +15.3%、cache-miss tokens +46.6%（注入块破坏 DeepSeek/GLM 前缀缓存的 system 前缀稳定性所致）、steps +6.7%。注入的字节代价小（共 78.7KB），但缓存失效的放大代价可观。
- 每注入任务的注入只发生在**首个用户轮**（33 任务×1 轮，非每轮重复），预算控制按设计工作。

## 5. 结果解读

1. **工程目标达成，收益假设未获支持**：修复把"注入结构性为零"变成"几乎全覆盖注入"，但注入的历史参考没有转化为 resolve 提升，反而带来可测的缓存成本。这与 spec §9.1 的第一性原理一致：L2 是低权威历史参考，本来就不该指望它直接提升解题率；其价值主张（若有）在减少重复探索/给出仓库操作知识，本轮 steps +6.7% 说明连这个也没兑现。
2. **负向结果本身是有效产出**：它否决了"撤除否决后注入越多越好"的路线，支持把下一步放在**注入质量**（逐卡适用性、task 匹配、更保守的注入时机——例如仅在库中有同 repo 强证据时注入）而非注入数量。当前 strict 对 3 个 repo 的任何累积卡片都会注入（包括 461B 的弱卡片）。
3. **缓存破坏是新的主要成本项**：未来任何注入策略都应评估 system/user 前缀稳定性对 prefix-cache 的影响（strict +46.6% cache-miss）。

## 6. 有效性边界

- n=35/臂、单次运行、无重复 seed：±1~3 题的摆动完全在二项噪声内，本实验**无统计功效检测小差异**；结论仅限"未见显著收益 + 成本侧负向"。
- 三臂并行（workers=2/臂）与历史轮的 workers=4 不同，绝对时长/超时数（off 14 vs 历史 10）不可跨轮比较；臂间对照不受影响（三臂同协议）。
- grader 为官方 SWE-bench 评价容器，calibration 正负对照通过；1 题（psf__requests-1963）为预判环境无效，三臂一致剔除。
- 全部 36 题原始轨迹、metrics、memory-extract 记录保留在各运行根 `batch/tasks/` 下，可复核。

## 7. 建议的后续（按性价比）

1. **注入门槛实验**（不跑模型也能先做）：用本轮 strict 轨迹离线重放，看"只注入同 repo 高分卡（zone=hit）"能砍掉多少低质注入与缓存损失。
2. prefix-cache 友好的注入布局（把块放稳定后缀而非扰动前缀）值得单独验证。
3. 若再做在线实验：n≥3 seeds 或 100+ 题才有功效；本轮的 33 任务注入覆盖与零故障基础设施可作为固定管线复用。

## 8. 四臂补充：Context-only 门控臂（issue #508 L1/L2，2026-09-25）

在 §5 结论（"注入质量而非数量"）之后，L0 离线重放显示注入字节 76% 已是 repo-ops（zone 门控有效），Memory=plan/outcome 垃圾仅 18%。据此跑两个门控臂（36 题、同协议同模型、campaign 侧库过滤；对照复用上文 off/strict）：ctx4096 = Context-only 门控；ctx1024 = 门控 + 预算 1024B。

| 臂 | resolve | 注入轮次/字节 | steps 均值 | prompt | cache-miss |
|---|---|---|---|---|---|
| off | 15/35 (42.9%) | 0 | 28.6 | 14.59M | 2.20M |
| strict（全量） | 14/35 (40.0%) | 33 / 78,744B | 30.5 | 16.81M | 3.23M |
| **ctx4096（门控）** | **18/36 (50.0%)** | 33 / 74,687B | 28.8 | **14.64M（≈off）** | 3.32M |

配对（36 题共同评分集）：ctx4096 独解 6 / off 独解 3；ctx4096 独解 5 / strict 独解 1。

判读（按 §7 预注册规则）：

1. **ctx4096 是四臂中唯一同时满足"resolve ≥ off 且 prompt 成本 ≈ off"的注入臂**：50.0% vs 42.9%（+7.1pt，配对 6:3），prompt tokens 与 off 持平（14.64M vs 14.59M，strict 为 16.81M）。方向与"剔除实例级垃圾卡"假设一致，且在全部配对中占优。但 n=35/36 单次运行，仍属方向性证据，不构成显著证明。
2. **ctx1024 判死**：预算 1024B 使过半任务零注入（16/36 轮），resolve 掉到 36.1%——过小预算消灭的是注入机会而非噪音。
3. **cache-miss 未随门控恢复**（3.32M ≈ strict 3.23M）：确认前缀缓存损失来自"注入块扰动首条 user 消息"这一位置事实，与注入内容质量无关。位置改造（稳定后缀注入）是恢复该项的必要手段，留待独立步骤。
4. **下一步建议**：保留 Context-only 门控作为 strict 默认（需把 campaign 侧过滤下沉为 kernel/bridge 的类型配置）；复跑一轮 ctx4096 以验证 50% 是否可复现；位置改造单独开题。

## 9. 深度分析：成本效率、噪声底与翻转解剖（2026-09-25，issue #508）

### 9.1 成本效率（每 resolve 的 prompt token）

| 臂 | prompt/resolve | 相对 off |
|---|---|---|
| off | 0.97M | — |
| strict | 1.20M | +24% |
| **ctx4096** | **0.81M** | **−16%** |
| ctx1024 | 0.89M | −8% |

ctx4096 是唯一在经济性上优于 off 的注入臂：每解决一题少花 16% 的 prompt token。即使 resolve 率差异全部归于噪声，"门控注入在成本效率上优于 strict 全量注入"（0.81M vs 1.20M，−33%）也是本轮最硬的可迁移结论。

### 9.2 运行间噪声底（历史同子集同模型三次运行）

同 36 题、glm-5.3-flash 的三次历史运行（pre447-0917 / strict-0917 / memflow-0918，代码版本略有不同）配对翻转：**任意两轮之间 3–5 题独解翻转是常态**；36 题中 9 题（25%）的判定在三轮间不稳定。ctx4096 对 off 的 +3 净胜（6:3）恰在噪声带上缘，对 strict 的 +4 净胜（5:1）超出一倍。方向一致、量级在噪声边缘——维持"方向性正向"的表述，不下显著结论。

### 9.3 翻转解剖（ctx4096 vs off 的 6 胜 3 负）

- 6 胜中 1 题（astropy-14995）实为 **off 臂基础设施故障**：step 1 即遭 relay 400 invalid_json（prompt 仅 5933 tokens），非记忆效应。诚实净胜为 **5:3**。
- 胜例分布在三个 repo，无单一 repo 支撑；astropy 2/6→4/6、pytest 5/14→6/15、django 四臂完全持平 8/15（django 库卡未在决定边际被使用）。
- 注入量与胜负无相关（胜例 5 轮/9,530B vs 负例 3 轮/6,576B）——数量不重要，与 §8 结论一致。
- steps：ctx4096 非截断均值 24.9 ≈ off 24.0，门控注入不增加探索步数（strict 的 25.4 略增）；max_steps 截断 7 次（off 8、strict 11）。

### 9.4 ctx1024 的组内选择效应

ctx1024 注入任务 resolve 7/16 (43.8%) vs 零注入任务 6/20 (30%)——组内差异与"注入=更晚、更相关的任务"的选择效应一致，不能当因果证据；这同时说明其低 resolve 主因是预算过早耗尽注入机会（16/36 轮），而非注入有害。

### 9.5 结论矩阵

| 命题 | 证据强度 | 判定 |
|---|---|---|
| 门控注入成本效率优于 strict 全量 | 强（−33% prompt/resolve，同协议） | 采纳 |
| 门控注入 prompt 成本 ≈ off | 强（14.64M vs 14.59M） | 采纳 |
| 门控注入 resolve 优于 off/strict | 方向一致（+7.1pt/配对 5:3），量级在噪声带边缘 | 待复跑 |
| 小预算（1024B）可行 | 反证充分（36.1%，16/36 轮注入） | 否决 |
| 缓存损失源于位置而非内容 | 强（门控后 miss 仍 3.32M） | 采纳，位置改造单列 |
