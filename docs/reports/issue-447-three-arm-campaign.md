## 2. 链路有效性（本实验的第一结论）

**记忆供给-注入全链首次在真实 SWE 基准上端到端工作。**

- strict 臂 33/36 任务产生真实 provider 交付的注入块（交付计数按 S8 新口径：仅 provider 接受后记录），3 个零注入任务全部是各 repo 的**第一个任务**（冷启动库为空——课程效应的预期行为，非缺陷）。
- 三臂分离严格符合设计：shadow 全程 0 注入但有 reuse 诊断；off 全程 0 注入。
- 注入块带完整溯源（source session / base commit / origin=session-auto / `applicability=historical_observation`）。
- 对照 2026-09-18 之前的状态（注入结构性不可达、实测 0），修复目标**已达成并经真实验证**。

## 3. 收益结论（必须诚实）

**resolve 差异不显著，不能宣称记忆注入提升了通过率。**

- strict 40.0% vs off 42.9%：配对差 −1 题（2 vs 3），在 n=35 下远在噪声范围内；shadow（有诊断无注入）反而最高 45.7%，说明臂间波动主要是模型随机性。
- **成本侧为负向信号**：strict 每 prompt tokens +15.3%、cache-miss tokens +46.6%（注入块破坏 DeepSeek/GLM 前缀缓存的 system 前缀稳定性所致）、steps +6.7%。注入的字节代价小（共 78.7KB），但缓存失效的放大代价可观。
- 每注入任务的注入只发生在**首个用户轮**（33 任务×1 轮，非每轮重复），预算控制按设计工作。

## 5. 结果解读

1. **工程目标达成，收益假设未获支持**：修复把"注入结构性为零"变成"几乎全覆盖注入"，但注入的历史参考没有转化为 resolve 提升，反而带来可测的缓存成本。这与 spec §9.1 的第一性原理一致：L2 是低权威历史参考，本来就不该指望它直接提升解题率；其价值主张（若有）在减少重复探索/给出仓库操作知识，本轮 steps +6.7% 说明连这个也没兑现。
2. **负向结果本身是有效产出**：它否决了"撤除否决后注入越多越好"的路线，支持把下一步放在**注入质量**（逐卡适用性、task 匹配、更保守的注入时机——例如仅在库中有同 repo 强证据时注入）而非注入数量。当前 strict 对 3 个 repo 的任何累积卡片都会注入（包括 461B 的弱卡片）。
3. **缓存破坏是新的主要成本项**：未来任何注入策略都应评估 system/user 前缀稳定性对 prefix-cache 的影响（strict +46.6% cache-miss）。

## 6. 有效性边界

- n=35/臂、单次运行、无重复 seed：±1~3 题的摆动完全在二项噪声内，本实验**无统计功效检测小差异**；结论仅限"未见显著收益 + 成本侧负向"。
- 三臂并行（workers=2/臂）与历史轮的 workers=4 不同，绝对时长/超时数（off 14 vs 历史 10）不可跨轮比较；臂间对照不受影响（三臂同协议）。
- grader 为官方 SWE-bench 评价容器，calibration 正负对照通过；1 题（psf__requests-1963）为预判环境无效，三臂一致剔除。
- 全部 36 题原始轨迹、metrics、memory-extract 记录保留在各运行根 `batch/tasks/` 下，可复核。

## 7. 建议的后续（按性价比）

1. **注入门槛实验**（不跑模型也能先做）：用本轮 strict 轨迹离线重放，看"只注入同 repo 高分卡（zone=hit）"能砍掉多少低质注入与缓存损失。
2. prefix-cache 友好的注入布局（把块放稳定后缀而非扰动前缀）值得单独验证。
3. 若再做在线实验：n≥3 seeds 或 100+ 题才有功效；本轮的 33 任务注入覆盖与零故障基础设施可作为固定管线复用。
