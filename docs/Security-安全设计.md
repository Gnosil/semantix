# Security 安全设计（Kernel 层 + 语义切片库）

> 本文档是 Semantix 的安全设计基线，与《Agent-Infra-架构设计.md》配套。
> 覆盖威胁模型、注入防护、缓存/切片库安全、代码执行安全、LLM judge 安全、
> 供应链与部署安全、可观测与审计、事故响应与安全检查清单。
> 所有对策均需实现为**确定性、可审计、可回滚**，与架构三铁律一致。

---

## 1. 威胁模型

### 1.1 资产（要保护的东西）

| 资产 | 位置 | 风险等级 |
|---|---|---|
| 切片库（用户代码、上下文块、工具调用模式、高频结果） | 本地磁盘（项目级/用户级双库） | 高——含用户代码与私有上下文 |
| 会话数据 / 历史 JSONL | 本地存储 | 高——可还原完整工作轨迹 |
| 缓存答案（L3 复用结果） | 本地缓存存储 | 中——可能含敏感生成内容 |
| 参数存储（进化引擎读写） | 本地 | 中——被篡改会改变调度/注入行为 |
| 本地凭证（API key、git 凭证） | 系统凭据链 | 高——泄漏即资源滥用 |
| 模型输出 / 工具结果 | 会话内瞬时数据 | 中——可能含不可信内容 |

### 1.2 攻击者与能力假设

| 攻击者 | 能力 | 关注面 |
|---|---|---|
| **恶意提示注入者**（通过网页/文件/外部内容） | 只能向"工具结果"或"历史会话"注入文本 | 注入传播（切片→注入→模型）、数据外带 |
| **历史污染者**（对过去会话内容有控制权） | 向切片库投毒 | 切片库注入、错误结果自我强化 |
| **工具参数注入者** | 通过不可信内容（文件/网页）诱导模型构造危险工具参数 | 路径穿越、命令注入、写越权路径 |
| **本地恶意进程** | 能读写本地文件/内存 | 切片库与凭证的本地泄露 |
| **网络窃听者** | 能观测本地与公网流量 | 明文泄露（DeepSeek 链路） |
| **供应链攻击者** | 替换依赖/模型文件 | 嵌入模型、HNSW 库、Ollama 服务被替换 |

### 1.3 信任边界（默认不可信清单）

```
可信（kernel 自身逻辑、本地参数存储、经净化的注入内容）
  │
  ├─ 不可信：一切外部内容 —— 网页抓取、文件内容、工具 stdout、LLM 输出
  ├─ 不可信：历史切片原文 —— 可能含旧会话中的注入载荷
  ├─ 不可信：模型输出 —— 可能被注入引导，只当数据不当指令
  └─ 不可信：远程 API 响应 —— 只解析约定格式，其余忽略
```

**核心原则：信任边界上的一切输入默认不可信；所有跨边界的文本在进入"注入区"或"judge 输入"前必须经过版本化规则引擎的确定性净化——确定性保证字节可复现（支撑 L2 注入集指纹），剥离完备性由对抗性测试集兜底（§3.1）。**

## 2. 安全设计原则

1. **不可信输入原则**：外部内容、历史切片、模型输出一律不可信，按数据而非指令处理；
2. **最小权限**：工具执行走权限门控链 `deny > sessionAllow > ask > allow > fallback`，写操作绝不自动放行；
3. **净化必须确定性**：`净化(输入) = 净化(切片 + 目标项目元数据)`，同输入必同输出；净化结果纳入注入集指纹。
   **注意：确定性 ≠ 完备性**——确定性只保证可复现，不保证剥离完备；对抗性注入可稳定绕过规则集。因此净化载体必须为**版本化规则引擎**（正则/签名库 + 敏感模式表），**禁止用 LLM 做净化判定**（LLM 输出不确定，会破坏注入集指纹）；规则集须配套**对抗性注入绕过测试集**，上线前验证剥离完备性（§10）。
4. **分级 fail 策略**：
   - **缓存层失败 → fail-open**（退化为基础 harness，绝不阻塞主循环，§架构 10-8）；
   - **安全边界失败 → fail-closed**（权限不确定即拒绝、沙箱不可用即不执行）；
5. **一切可回滚、可审计**：每个注入/预取/复用决策带 `id + reason`，逐组件 ablation 开关；
6. **数据最小化**：切片库与遥测分离——用户代码/上下文**不进 telemetry**，本地可脱敏、可一键清空。
7. **参数存储完整性**：进化引擎参数存储带版本 + 完整性校验（HMAC/签名），检测到篡改即回滚上一版本并告警（防本地恶意进程篡改调度/注入行为）。

## 3. 注入攻击与对策

### 3.1 切片库注入（L2 注入路径）——最高优先级威胁

**威胁**：历史会话中的恶意内容（用户粘贴的"忽略之前指令"类文本、工具读取的恶意文件）被提取为切片 → 跨会话注入到新会话的前缀区 → 污染模型行为，且**跨会话传播**。

**对策**（对应架构 §4.2 注入净化，此处固化要求）：
1. **注入前净化**：命中切片的 `Content` 在注入前必须过注入检测与脱敏——剥离提示注入特征（指令前缀、角色扮演、命令替换等），并对密钥、邮箱、内网路径等敏感模式做脱敏替换；
2. **净化确定性**：`净化(切片, 目标项目元数据)` 必须是纯函数，同输入同输出——净化结果纳入注入集指纹，参与"字节稳定"判定。**净化只用版本化规则引擎，不用 LLM**（LLM 不确定性破坏注入集指纹）；规则集配套对抗性注入绕过测试集，验证剥离完备性（§10）；
3. **跨项目隔离**：用户级切片跨项目注入时，剔除项目专属路径、密钥、占位符内容；
4. **污染信号闭环**：用户编辑/回滚注入块 → `rejected++` → 切片降权 → 低权威注入。

### 3.2 LLM judge 输入注入（L3 验证路径）

**威胁**：Krites 式 judge 读取历史切片 `(s, a)` 时，切片内容中的注入载荷劫持 judge，导致**系统性误批**（把不可复用的结果批成可复用）。

**对策**：
1. judge 只能读**净化后**的切片（复用 §3.1 的净化管线，禁止读原文）；
2. judge 输出**单 token（APPROVE/REJECT）+ temperature 0**，把注入影响面限制为二选一；
3. judge 调用频率受 `τ_low` 与限流约束（见 §6），降低暴露窗口。

### 3.3 工具输出注入（执行路径）

**威胁**：工具返回内容（网页 HTML、被篡改的文件、`curl` 结果）包含指令 → 模型被引导调用危险工具。

**对策**：
1. 工具结果按**数据**处理，绝不作为指令回注；模型只"读"工具结果，修改会话的权限在 harness 侧受控；
2. 危险工具（写文件、执行命令、发网络请求）默认走权限门控，不因内容诱导自动放行；
3. 工具输出长度与敏感模式过滤（防把密钥/内网地址整段喂给模型）。

### 3.4 数据外带（exfiltration）

**威胁**：模型被注入引导读取敏感文件（`.env`、SSH key、`~/.git-credentials`）并把内容输出到外部渠道。

**对策**：
1. **工具权限白名单（默认 deny）**：文件读取按路径规则过滤，**基线敏感清单**：`.env*`、`*credentials*`、`.ssh/`、`.git/`、`id_rsa*`、`*secret*`、`*token*`、系统凭据目录——命中即 deny，未列入的敏感路径由 deny 基线兜底；
2. **外带阻断**：模型输出与工具结果中的可疑模式（长密钥、凭证格式）**记录并阻断**（截断/替换后继续），不只记日志；
3. **沙箱只读映射**：高危读取场景在 OS 沙箱内以最小只读文件集执行（见 §5）；
4. **不进 telemetry**：即使发生泄露，切片库/遥测也不额外放大泄露面。

## 4. 缓存与切片库安全

### 4.1 错误结果自我强化（L3 最危险的失效模式）

**威胁**：L3 命中返回错误/过期答案 → 若用户未否决，切片权重上升 → 后续更多查询命中该错误 → **错误被系统自我强化**。

**对策**（fail-closed，对应架构 §4.3）：
1. 复用条件全满足才命中：意图指纹 + 输入指纹 ≥ τ' + **可验证**（mtime/SHA 未变 + 只读白名单 + 24h 超时 + 不依赖会话内未知状态）；
2. **展示来源切片**：每次 L3 命中向用户展示来源，用户可否决；
3. 否决即失效：`rejected++` → 切片降权 → 从可复用集剔除；
4. **写操作绝不复用**：只读任务白名单，写操作结果永不进 L3。

### 4.2 缓存污染传播

**威胁**：被污染的切片经"提升"（auxiliary overwrite，未来 Krites 式）扩散到更多 key，且切片更新后旧条目仍生效。

**对策**：
1. **版本号传播**：每个提升条目带 `source` 切片 id + 版本号；切片更新 → 按 source 级联失效或重审相关条目；
2. **static-origin 标记**：提升条目标记来源，支持一键批量清除/重审；
3. **污染检测**：污染信号同 §3.1.4（用户编辑/回滚、注入检测命中、用户否决），此处从缓存视角补充：提升条目按 source 批量回收（§4.2.2），信号计入进化引擎（§架构 6.1）；
4. **容量有界**：提升条目沿用 LRU/TTL 淘汰，不因"已验证"而免除淘汰（Krites §3.3 语义）。落地（2026-08-16）：切片库上限默认 5000（`store.max_slices`），超限按价值评分升序归档；Weight 只进淘汰排序、检索永不读——§4.1 的自我强化回路在结构上不存在。

### 4.3 隐私与数据最小化

**威胁**：切片库与缓存存有用户代码、项目结构、个人偏好，若被读取或上传即隐私泄露。

**对策**：
1. **全程本地**：切片库、缓存、参数存储均本地持久化，无远端同步；
2. **可脱敏**：注入/入库前对密钥、邮箱、内网路径等做脱敏替换；
3. **可清空**：提供一键清空切片库/缓存的能力，清空后系统退化为基础 harness（fail-open 路径）；
4. **不进 telemetry**：切片内容、会话原文、工具结果禁止进入任何外部遥测/分析通道。

## 5. 代码执行安全（工具层）

工具执行是 kernel 的全部"副作用出口"，按纵深防御组织：

```
权限门控（决策）→ OS 沙箱（隔离）→ 快照安全网（回滚）
```

1. **权限门控链**：`deny > sessionAllow > ask > allow > fallback`；默认 deny，白名单放行；写操作必须显式授权；
2. **OS 沙箱**：Seatbelt（macOS）/ bubblewrap（Linux）/**Windows 等效隔离（受限令牌 + AppContainer，或部署时在容器/WSL 内运行）**，**fail-closed**——沙箱不可用时拒绝执行；
3. **快照安全网**：写操作前对目标文件做快照，失败/回滚可还原；
4. **并发边界**：只读工具并行 ≤ 8（allSettled 语义）；写工具串行屏障（保序）；行为学习候选组必须过静态数据依赖检查才能并入并发组（对应架构 §5.1）；
5. **会话内注入防护**：工具执行参数只由 kernel 显式构造，不直接拼接不可信内容。

## 6. LLM judge 安全（未来 Krites 式验证）

| 风险 | 对策 |
|---|---|
| judge 被切片注入劫持 | 只读净化后切片；单 token 输出；temperature 0 |
| false-approve 传播错误 | 错误上界 `增量错误率 ≤ ε_fa × p_prom`；实测 ε_fa；提升条目带来源可批量回滚 |
| judge 调用成本失控 | `τ_low` 旋钮 + 限流 + 去重（同一 (q,s) 不重审）+ 重试退避 |
| judge 输出不可复现 | 单 token + temperature 0 + 严格 rubric（意图对齐/实体约束一致/新鲜度个性化） |
| 评估自欺 | oracle 主实验测策略价值 + ≥300 对人工审计样本测 judge 一致性，两个数字分开报告 |

## 7. 供应链与部署安全

1. **依赖来源固定**：embedding 模型（bge-m3/Ollama）、HNSW 库、harness 版本均锁定版本与校验和；Ollama 仅监听本地回环（`127.0.0.1:11434`），不暴露公网；
2. **凭证管理**：API key 走系统凭据链（keyring）；keyring 不可用时**拒绝启动或要求显式环境变量注入**（不回退到明文文件）；git 凭证遵循系统 git credential helper，kernel 不自行存储；凭证仅在请求构造时**进程内**传递，**禁止**写入切片库、会话 JSONL、日志；日志与遥测脱敏；凭证**定期轮换**并支持多 key 热切换；
3. **传输安全**：与 DeepSeek 的通信强制 HTTPS（`https://api.deepseek.com`）；本地组件（Ollama/Milvus）仅绑定回环地址，**且启用本地认证**（unix socket 文件权限或 loopback token）——回环绑定防不了本地恶意进程直连嵌入服务/替换模型，须做**运行时服务身份校验**（进程/二进制指纹），校验失败即 fail-closed 拒绝调用；
4. **最小组件面**：kernel 不引入不必要的网络监听；无公网入站端口；
5. **模型输出处置**：模型输出视为不可信数据，任何写入切片库/缓存的内容先过净化和敏感模式过滤。

## 8. 可观测与审计

1. **决策可解释**：每次注入/预取/复用带 `id + reason`（命中哪个切片/哪个信号源），与架构 §6.3 一致；
2. **安全事件计数**：注入检测命中数、用户编辑/回滚数、L3 否决数、judge 拒绝数均作为观测指标（不进外部遥测，本地仪表）；
3. **审计日志**：工具执行（含权限裁决结果）、切片入库（来源+净化动作）、参数变更（谁/何时/冻结期）记录本地审计日志；
4. **分环节计费埋点**：仅记录费用与 token 数，不记录内容（分路径成本模型：L3 零费 / L2 输入 hit 价+输出全价 / 未命中全价——目前仅存在于对话讨论，建议后续在架构文档**新增** §4.4 章节落地）。

---

## 9. 事故响应

1. **一键关闭**：注入/预取/复用逐组件 ablation 开关，可单组件停用（对应架构 §6.3）；
2. **切片库整体重建**：检测到系统性污染时，清空切片库/缓存 → 系统退化为基础 harness（fail-open），重训/重建后恢复；
3. **参数回滚**：冻结期参数存储保留上一版本，异常收敛可回退；
4. **提升条目批量回收**：按 `static-origin` / source 版本号批量失效（对应 §4.2）。

## 10. 安全检查清单（开发 / 上线前逐项打勾）

**注入与净化**
- [ ] 注入净化管线确定性（同输入同输出），净化结果纳入注入集指纹
- [ ] 净化载体为版本化规则引擎（非 LLM），对抗性注入绕过测试集通过
- [ ] 用户级切片跨项目注入时剔除项目专属路径与密钥
- [ ] judge 只读净化后切片，禁止读原文
- [ ] 工具输出按数据处理，不按指令回注
- [ ] 敏感路径基线清单生效（默认 deny，命中即阻断），外带检测阻断而非仅日志

**缓存与 L3**
- [ ] L3 复用满足全部 fail-closed 条件（指纹+可验证+白名单+24h）
- [ ] L3 命中展示来源切片，用户否决即失效并计数
- [ ] 写操作结果永不进 L3
- [ ] 提升条目带 source+版本号，级联失效路径可用

**执行与权限**
- [ ] 权限门控链默认 deny，写操作显式授权
- [ ] OS 沙箱 fail-closed（不可用即拒绝执行）
- [ ] 写前快照 + 回滚路径验证
- [ ] 并发组全部通过静态数据依赖检查

**数据与隐私**
- [ ] 切片库/会话/缓存全程本地，无远端同步
- [ ] keyring 不可用时不回退明文存储（拒绝启动或环境变量注入）
- [ ] 本地服务（Ollama/Milvus）启用本地认证 + 运行时身份校验
- [ ] 切片与日志不含明文凭证（keyring 管理）
- [ ] 一键清空切片库/缓存能力验证通过
- [ ] 内容类数据不进外部 telemetry

**供应链与网络**
- [ ] 依赖/模型版本锁定 + 校验和
- [ ] Ollama/Milvus 仅绑定回环地址
- [ ] DeepSeek 通信仅 HTTPS

**judge（若启用）**
- [ ] 单 token + temperature 0 输出
- [ ] 限流/去重/重试生效
- [ ] ε_fa 实测，错误上界公式可用
- [ ] oracle 与真实 judge 两个评估数字分开报告
