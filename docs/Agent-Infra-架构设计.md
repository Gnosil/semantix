# 自进化 Agent Infra 架构设计（Kernel 层 + 语义切片库）

> 目标：构建一个**独立于具体 harness 的 kernel 层**——在 agent looping 期间，
> 基于**用户使用习惯**动态调配 harness 内全部资源：能并发的并发、
> 能语义缓存的语义缓存、能投机预取的就预取；并通过「习惯 → 语义切片库 →
> 决策 → 反馈」的闭环，让系统在资源与能力上**自进化**。
>
> 设计基线：DeepSeek-Reasonix（Go 版，`main-v2` 分支，
> https://github.com/esengine/DeepSeek-Reasonix，MIT）的缓存优先架构（前轮已逐行核实）；
> 文中所有 file:line 引用均指向 `main-v2` 分支。

---

## 0. 问题定义

### 0.1 我们要解决的痛点（现状的四个浪费）

| # | 浪费 | 现状（以 Reasonix 为参照） |
|---|---|---|
| 1 | **跨会话缓存失效** | 前缀缓存只在**同一会话内**按字节命中；新会话处理同样的任务/项目，一切从头建立，用户习惯完全没有被复用 |
| 2 | **缓存命中是被动的** | 现有机制只保证"前缀不变"（被动不失效），从不**主动复用**相似内容；相似但不字节相同的上下文 100% 重付 |
| 3 | **调度是静态规则** | 并发判定是工具 schema 级静态 `ReadOnly()`；模型 tier 是固定预设；不学习"这个用户在这个项目里实际怎么干活" |
| 4 | **等待期资源闲置** | 模型流式输出期间（往往数秒到数十秒），本地 CPU/网络/索引全部空闲——没有任何投机预取 |

### 0.2 我们的目标

1. **语义切片库（Semantic Slice Library, SSL）**：从用户历史会话中提取可复用的
   "语义单元"（任务模板、上下文块、工具调用模式、高频结果），带向量索引持久化；
2. **语义缓存**：在现有字节前缀缓存之上，加一层"语义层"——跨会话复用相似切片，
   并用"稳定切片注入"反过来**喂养**字节级前缀缓存（见 §4.2 关键机制）；
3. **Kernel 调度器**：以"当前应用目的"（intent）为纲，对工具并发、模型 tier、
   缓存注入、预取做**联合决策**，并随习惯进化；
4. **自进化闭环**：每次调度的结果（命中/浪费/延迟/成本/用户反馈）回写统计，
   在线调整决策参数，离线周期重训练。

### 1.2 必须补齐的六项局限

1. 缓存**会话内** → 语义库**跨会话**（L2/L3 层）；
2. 缓存**被动** → 主动**检索+注入+复用**；
3. 调度**静态** → **行为模式学习**（从 T-Slice 统计转移概率）；
4. **无预取** → 预取器填满等待期；
5. 记忆只存**陈述性事实**（用户说"我喜欢 X"）→ 补充**程序性行为模式**
   （用户实际总做 A→B→C），这是"自进化"的数据基础；
6. 上下文管理只**删不换**（compaction 丢弃旧内容）→ 我们**按价值重新注入**
   高频切片（删掉的是低频，换进来的是高频）。

```
│                                                                 │
│  ③ 联动层：记忆（陈述性）⇄ 切片库（程序性）⇄ 线程/会话态 ⇄ 项目态 │

└─────────────────────────────────────────────────────────────────┘
```

**三条铁律**（贯穿所有组件，继承 Reasonix 教训）：
1. **系统前缀永不改，可变内容走尾部**——system/tools/记忆索引字节不变；
   跨会话稳定的 L2 注入块位于系统前缀之后，受「规范序 + 冻结期」约束（§4.2）；
   会话内可变内容（记忆更新等）仍走 turn 尾部；
2. **只读才预取/并发**——有副作用的操作绝不投机；
3. **一切决策可回滚**——每次注入/预取/复用都带 id，可一键关闭（ablation）。

## 3. 语义切片库（SSL）——系统的"习惯记忆"

### 3.1 切片类型（五种，按来源与用途分）

| 类型 | 内容 | 复用方式 | 示例 |
|---|---|---|---|
| **P-Slice** 提示词切片 | 任务模板、高频指令块 | L2 注入 | "先跑 `go test ./...` 再提交" |
| **C-Slice** 上下文切片 | 项目结构摘要、常用文件、偏好块 | L2 注入 | 项目入口/构建命令/关键路径 |
| **T-Slice** 工具模式切片 | 工具调用**序列**（行为模式） | 调度/预取 | `grep` → `readFile` → `editFile` |
| **R-Slice** 结果切片 | 高频复用的工具结果/回复 | L3 复用 | 常用代码片段、FAQ 式解答 |
| **M-Slice** 记忆切片 | 与记忆系统联动的语义单元 | 注入+进化 | 记忆索引块的向量投影 |

### 3.2 切片生命周期（提取 → 嵌入 → 索引 → 评分 → 淘汰）

```
会话 JSONL ──► ①提取器（增量，按语义边界切分）
                · 边界信号：turn 边界 / 任务完成点（final answer 前后）/
                  工具序列的稳定 n-gram / 用户编辑回滚点（注入污染信号）
                · 切分预算：切片 token 上限（默认 2k，可配）
     ──► ②嵌入器：本地 embedding 模型（bge-m3 / Ollama），维度 ≤1024，
                  P/C/R/M 用文本嵌入；T-Slice 用「工具名序列」单独嵌入空间
     ──► ③ANN 索引：HNSW（磁盘持久化），项目级 + 用户级双库
                  （用户习惯跨项目复用；项目模式项目内复用）
     ──► ④评分器：价值 = f(命中率, 时效衰减 exp(-λt), 用户反馈±, 
                          意图相关度, 注入成功率)
     ──► ⑤淘汰器：容量预算（磁盘/内存双层）；价值低于阈值的降级/归档
```

### 3.3 关键数据结构

```go
type Slice struct {
    ID          string      // 稳定 UUID（内容更新不换 ID，保住统计连续）；sha256 仅作版本字段
    Type        SliceType   // P/C/T/R/M
    Scope       Scope       // project | user | session
    Content     []byte      // 规范化文本（P/C/R/M）或工具序列（T）
    Embedding   []float32   // 向量（T 用序列嵌入）
    Stats       SliceStats  // hits / misses / injected / rejected / lastUsed
    Weight      float64     // 价值权重（进化引擎更新）
    Meta        SliceMeta   // 来源会话、任务类型、语言、项目 slug
}

type SliceStats struct {
    Hits, Misses, Injected, Rejected uint64
    LastUsed, FirstSeen              time.Time
    UserFeedback                     float64 // +1 保留 / -1 拒绝 / 0 无
}
```

> 落地注（2026-08-16）：实现中 `LastUsed` 为 unix 秒 `int64`（journal max-merge 合并）；
> `FirstSeen` 不单独落盘——语义等同 `Slice.CreatedAt`，刻意去重。评分器④/淘汰器⑤
> 已落地于 `kernel/slice`（score.go + GC 上限/归档），见 `docs/specs/slice-value-eviction.md`。

### 3.4 与记忆/线程的联动

- **记忆（陈述性）**：`remember` 存的偏好 → 作为 C-Slice 的种子内容；
  切片库观测到的行为模式 → 反向生成记忆建议（"你最近总在 X 项目用 Y 流程"）；
- **线程（会话态）**：线程边界决定切片作用域；`resume` 的会话直接贡献切片；
- **项目态**：项目结构索引（tree-sitter 语义索引，Reasonix 已有 codeIndex）→ C-Slice 原料。

## 4. 语义缓存引擎——三层缓存

### 4.1 三层缓存总览

| 层 | 作用域 | 命中条件 | 成本 | 正确性风险 |
|---|---|---|---|---|
| **L1 字节前缀** | 同会话 | 字节级前缀稳定（沿用 Reasonix 机制） | ~0 | 无（厂商保证） |
| **L2 语义块注入** | 跨会话 | 当前意图/上下文与 P/C/M-Slice 语义相似 ≥ τ | 注入 token 成本 | 中（内容可能过时/不适配） |
| **L3 语义结果复用** | 跨会话 | 意图指纹 + 输入指纹相似 ≥ τ'，且**可验证** | ~0（不发请求） | 高（结果可能错误/过期） |

### 4.2 L2：稳定切片注入（核心创新）

**机制**：命中切片后，不是把"相似内容"自由改写塞进去，而是**原样注入同一切片**
（字节稳定），并在注入时打标记 `<slice id=...>`。

**为什么这是关键**：
- 同一任务族的新会话，注入的是**同一组字节相同的切片**（检索确定性 + 冻结期保证）；
- 注入块位于系统前缀之后、用户消息之前 → 新会话**首轮请求即命中**
  至注入块末尾的字节缓存，后续轮次继续在此基础上稳定增长；
- 于是 **DeepSeek 自动前缀缓存被"语义层喂养"**：跨会话的语义命中，转化成了
  厂商能识别的字节命中。这是在对现有 API（无显式 KV-cache 控制）约束下的最优解；
- 未来若厂商开放显式 KV cache / cache-control API，L2 可直接升级为
  "服务端缓存 pin"，注入层退化为 fallback。

**注入规则**（与 Reasonix 尾部原则的差异是刻意的，理由如下）：
```
注入位置：系统前缀之后、用户消息之前（注入块是新会话公共前缀的一部分，
          首轮即可命中字节缓存——这是"语义层喂养字节层"成立的前提）
注入顺序：固定规范序（切片 ID 升序），绝不按价值排序——顺序可变即前缀失效
注入粒度：整切片注入；超预算按"价值排序"整切片取舍，绝不从切片中间截断
           （截断产生不稳定字节，同样破坏前缀）
注入稳定性前提：检索必须确定性（同一输入 → 同一 top-k 集合），且注入集
          实行**快照锁定**——参数变更（§6.2 冻结期）与库增量变更均延迟至
          冻结期结束才生效，保证同一任务族跨会话注入集字节不变
注入净化：切片内容注入前过注入检测与脱敏（防历史内容中的 prompt injection
          跨会话传播）；用户级切片跨项目注入时剔除项目专属路径/密钥；
          净化输出必须确定（净化输入 = 切片 + 目标项目元数据，同输入同输出），
          净化结果纳入注入集指纹
验证与回滚：用户编辑了注入块 / 会话出现回滚 → rejected++ → 降权
```

### 4.3 L3：结果复用（带验证，fail-closed）

**可复用条件**（全部满足才命中）：
1. 意图指纹（intent + 任务类型 + 工具序列签名）相似 ≥ τ'；
2. 输入指纹（用户消息规范化 hash 或语义）相似 ≥ τ'；
3. **可验证性（具体手段）**：结果依赖的输入文件做 mtime/SHA 指纹校验
   （文件未变才可复用）；仅限检索/问答/解释类只读任务白名单；不依赖会话内
   未知状态；附带"生成时间 + 来源切片"，超时（默认 24h）自动失效；
   L3 命中不发模型请求 → 无模型输出可做完成度检查，故每次 L3 命中仍向用户
   展示来源切片，用户否决即失效并计入 rejected（防错误结果自我强化）；
4. 只复用**只读任务**的结果（检索、问答、解释类），绝不复用写操作结果。

## 5. 调度器 + 投机预取——资源编排

### 5.1 调度器（Scheduler）

**输入**：intent 分类、切片命中集、T-Slice 行为模式、资源状态（并发槽位、模型 tier、预算）。

**决策输出（每次工具轮）**：
1. **并发划分**：静态 `ReadOnly()` 基线（Reasonix 已验证）+ **行为增强**——
   从 T-Slice 统计的"用户常并行的调用组"仅作**候选**，仍须通过静态数据依赖
   检查（ReadOnly + 参数路径分析）才并入并发组；
2. **模型 tier**：intent 分类（简单问答 → flash；跨文件重构 → pro）+
   行为学习（该任务类型历史成功率低 → 提前升级）；
3. **注入计划**：L2 切片清单（§4.2）；
4. **预取清单**：交给预取器（§5.2）；
5. **预算门控**：所有决策合计 token/并发预算，超预算按优先级裁剪。

**调度优先级**：正确性 > 缓存命中 > 并发度 > 预取。

### 5.2 投机预取器（Prefetcher）

**预测来源**（三个信号源，加权投票）：
1. **T-Slice 转移概率**：`P(工具B | 工具A)`，从历史会话统计的 n-gram
   （如 `grep "func X"` → 87% 概率 `readFile` 命中文件）；
2. **文件路径模式**：用户高频编辑的文件集（`build.gradle` 后常跟
   `src/main/...`），项目内路径转移矩阵；
3. **语义相似**：当前工具参数与历史会话中相似调用的后续步骤。

**预取规则**：
- **只预取只读资源**：以"下一轮模型请求的切片组装 + embedding 查询"为主
  （参数可提前确定、收益可量化）；文件内容预热（毫秒级读取，收益存疑）与
  grep/glob 结果（依赖尚未产生的参数）列为低优先级，P4 阶段量化后再启用；
- **时机**：模型流式等待期 / 工具执行间隙（latency hiding）；
- **预算**：预取并发 ≤ 2、单次预取 token 预算 ≤ 2k；失败记 `waste++`，
  `waste/hit` 超过阈值（默认 3:1）自动降低该信号源权重——**预取也要自进化**。

## 6. 进化引擎——自进化闭环

> **结构约束**：进化引擎只**读写参数存储**，不回调调度/缓存/预取决策链——
> 各决策组件单向依赖参数存储（读最新参数），避免循环依赖；§2 图中组件间的
> 双向箭头在实现上均为"经参数存储间接交互"，而非直接互调。

### 6.1 信号采集（每轮都有）

| 信号 | 来源 | 用途 |
|---|---|---|
| 缓存命中/未命中（L1/L2/L3） | 缓存引擎 | 阈值 τ/τ' 调整 |
| 注入污染（用户编辑/回滚注入块） | harness 事件 | 切片降权 |
| 预取 hit/waste | 预取器 | 信号源权重 |
| 端到端延迟/成本 | Usage 事件 | 预算与 tier 决策 |
| 任务成功率 | 完成度检查（Reasonix evidence） | 调度优先级 |
| 用户显式反馈（approve/reject/star） | 交互事件 | 切片价值 ± |

### 6.2 两层更新

- **在线（每轮 EWMA）**：命中率/延迟/污染的滑动平均 → 直接调参数
  （τ、τ'、注入预算、预取阈值、并发度、tier 映射）；
  **注入集冻结期**：参数变更后注入集在冻结期（默认 ≥1 小时）内保持不变，
  防止进化参数抖动摧毁它自己喂养的字节缓存（§4.2）；
- **离线（周期，如每日/每项目里程碑）**：切片嵌入刷新（embedding 模型升级）、
  阈值网格搜索（在历史数据上模拟调度找最优参数）、T-Slice 转移矩阵重训、
  低频切片归档。

### 6.3 自进化的三个"度"

1. **冷启动**：无习惯数据时用保守默认（τ 高、不预取），行为学习从静态基线开始；
2. **漂移适应**：用户换项目/换语言/换任务类型 → 相关信号源权重自动下降，
   新习惯快速爬升（EWMA 窗口自适应）；
3. **可解释与可关**：每个决策带 reason（命中哪个切片/哪个信号源），
   ablation 开关逐组件关闭（沿用 Reasonix `ablation` 包的思路）。

## 7. 一次请求的完整数据流

```
用户输入
  │
  ▼
① Harness 事件流（TurnStarted + 输入）→ kernel
  │
  ▼
② 目的感知器：embedding + 规则 → intent（修 bug/加功能/重构/测试/问答…）
  │
  ▼
③ 语义缓存引擎：双库检索 top-k（阈值 τ 拦截）
  │   ├─ L3 命中（可验证）→ 直接复用结果（不发模型请求）→ ⑤
  │   └─ L2 命中 → 组装稳定切片注入清单（预算内按价值整切片取舍，
  │      顺序固定规范序 ID 升序）
  │
  ▼
④ 调度器联合决策：并发组 / tier / 注入清单 / 预取清单
  │   └─ 预取器在模型等待期预热只读资源（预算内）
  │
  ▼
⑤ 执行轮（harness 主循环，与 kernel 无侵入）：
  │   工具轮 → 事件流上报 → kernel 记录行为（T-Slice 增量）
  │   └─ 注入块在前缀区且字节稳定 → 本轮起 L1 命中（首轮即命中至注入块末尾）
  │
  ▼
⑥ 回合结束：进化引擎吸收全部信号 → 更新统计与参数
  │   新切片入库（增量提取）· 权重更新 · 预取/阈值微调
  ▼
⑦ 会话落盘 → 供跨会话提取（下一次"我"更强）
```

## 8. 设计理由（逐决策）

| 决策 | 理由 |
|---|---|
| **kernel 独立于 harness** | 不绑死单一 harness（Reasonix/Claude Code/自研都可用）；Reasonix 的 event.Sink 就是现成 hook 点；复用"单 Controller 多前端"哲学为"单 kernel 多 harness" |
| **稳定切片注入放在前缀区、字节稳定** | 与 Reasonix"可变内容走尾部"的差异是刻意的：注入的是跨会话稳定块，放在系统前缀之后可让新会话首轮即命中字节缓存，把缓存从会话内扩展到任务族——语义层与字节层不是替代而是喂养关系（§4.2 是全文最核心的洞察）；会话内可变内容仍走尾部 |
| **三层缓存** | 成本与风险递增：L1 免费无风险（沿用）、L2 有 token 成本但跨会话（主力）、L3 零成本但高风险（fail-closed 验证）。让廉价层先命中 |
| **切片带价值评分与淘汰** | 语义库无限增长会拖慢检索、污染注入；价值函数 = 命中×时效×反馈，保证库"越用越准"而非"越用越大" |
| **双库（项目/用户）** | 用户习惯跨项目复用（如"提交前跑测试"），项目模式项目内强相关（如构建命令）；避免用户库被项目噪声稀释 |
| **行为模式（T-Slice）≠ 记忆** | 记忆是用户**陈述**的偏好（陈述性知识）；行为模式只能**观测**（程序性知识）。自进化的数据基础正是后者——"用户说的"和"用户做的"经常不一致，以做的为准 |
| **预取只读 + 预算 + 浪费惩罚** | 预取本质是赌博：只赌无副作用的资源；用 hit/waste 比例约束赌博频率，让预取器自己学会"什么时候值得赌" |
| **目的感知用 embedding+规则而非大模型** | 每轮意图分类若调 LLM，成本吃掉缓存收益；embedding 相似度 + 轻量规则已够（粒度粗一点没关系，调度器容错） |
| **进化分在线/离线两层** | 在线 EWMA 秒级适应习惯漂移；离线重训处理需要全局视野的优化（阈值搜索、嵌入刷新）；两者共用同一信号集 |
| **一切可回滚、可解释** | 注入/预取/复用都是概率性决策，必有失败；带 id + 带 reason + ablation 开关，保证系统"坏了能关、能定位"——这是能长期自进化的前提（不做黑盒） |

## 9. 落地路线图（每阶段可独立交付）

| 阶段 | 内容 | 交付物 | 依赖 |
|---|---|---|---|
| **P0 观测层** | harness 适配器 + 事件流采集 + 统计基线 | kernel 骨架、命中率/延迟/成本仪表 | 无 |
| **P1 切片库** | 提取器 + 嵌入器 + HNSW 索引 + 双库 | 可查询的 SSL + CLI 检索工具 | P0 |
| **P2 语义缓存** | L2 稳定注入 + L3 验证复用 + 污染检测 | 跨会话缓存命中率显著提升 | P1 |
| **P3 调度器** | intent 分类 + 并发行为学习 + tier 决策 | 调度计划可视化（每轮决策可解释） | P0/P2 |
| **P4 预取器** | T-Slice 转移矩阵 + 路径模式 + 预算控制 | 等待期利用率提升 | P1/P3 |
| **P5 进化闭环** | 在线 EWMA + 离线重训 + ablation | 全自动自进化（可观测参数收敛） | P2-P4 |

**建议首个落地载体**：在 Reasonix 上做 P0+P1 原型（hook 现成 event 流，
复用其 `store`/`history` 数据），验证「稳定切片注入 → L1 命中率跨会话提升」
这一核心假设（§4.2）后再扩展。

## 10. 风险与边界（诚实声明）

1. **正确性风险（最大）**：语义相似 ≠ 语义等价。注入过期/不适配切片会污染模型
   → 对策：低权威注入 + 污染检测（用户编辑/回滚信号）+ 可一键关闭 + L3 严格验证；
2. **延迟开销**：embedding + ANN 检索本身有延迟（本地 bge-m3 约 10-50ms/批）——
   必须小于省下的模型延迟；P0 就要测这条账；
3. **隐私**：切片库存用户代码/上下文 → 全程本地、可脱敏、可清空、不进 telemetry；
4. **API 约束**：DeepSeek 当前无显式 KV-cache 控制 → L2 只能 prompt 注入
   （§4.2 已把此约束转化为设计优势）；若未来开放 cache-control，L2 升级为 pin；
5. **模型输出漂移**：注入切片改变了模型看到的输入 → 输出可能变化；
   以"注入前后任务成功率/用户编辑率"为质量闸门，恶化即回退；
6. **库膨胀**：切片库无限增长 → 价值评分 + 淘汰器 + 容量预算兜底；
7. **多 harness 差异**：不同 harness 事件契约不同 → 适配层做事件规范化
   （统一为 kernel 内部事件模型，Reasonix event 为第一方言）；
8. **失败路径策略（fail-open）**：嵌入模型挂掉 / ANN 检索超时 → 跳过语义层
   直接放行（退化为基础 harness），缓存层失败绝不能阻塞主循环；索引版本
   变更时注入集按冻结期规则平滑过渡；

## 11. 验证指标（成功标准）

| 指标 | 目标（P5 后） |
|---|---|
| L2 跨会话命中率 | ≥ 40%（同一任务族新会话首轮即命中） |
| 综合缓存命中（L1+L2，token 计） | ≥ 90% |
| 每任务成本 | 较无 kernel 基线下降 ≥ 50% |
| 等待期利用率（预取覆盖率） | ≥ 30% 的工具等待窗口被利用 |
| 注入污染率（用户编辑/回滚） | ≤ 5%，且随进化单调下降 |
| 端到端延迟 | 不高于基线（检索+注入开销被命中收益覆盖） |
